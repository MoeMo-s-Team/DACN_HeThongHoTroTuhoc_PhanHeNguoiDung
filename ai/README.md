# AI runtime and benchmark

The Python service is a Colab demonstration runtime. It listens on `127.0.0.1`; expose it to NestJS only through an owner-authorized private network path. This repository never starts a public tunnel.

## Phase 1D.3-Lite demo

Run `ai/colab/phase-1d3-lite.ipynb` with **Run all** on a Tesla T4. Provide the owner-authorized repository URL and immutable 40-character commit SHA when prompted; the runtime token is entered in a hidden prompt. By default, this diagnostic run sends only the synthetic `ADMIN_FEEDBACK_GROUPING_STAGE1` fixture. Stage 1 uses constrained decoding from its existing output schema to prevent wrappers and invalid JSON structure; NestJS still performs its existing validation. To capture raw-generation evidence for this one synthetic fixture, set `ENABLE_LITE_DIAGNOSTICS = True` in the first code cell before **Run all**; the notebook verifies one diagnostic file under `diagnostics/` with directory mode `0700` and file mode `0600`, without request input, prompt, or auth token. Change `LITE_TASK_FILTER` to `all` and `RUN_LIVE_NESTJS_SMOKE` to `True` only when a full Lite rerun is needed. The notebook preserves Colab's existing Torch, runs `prisma generate` after install, and writes each attempt under a unique `/content/lite-evidence` run directory. This targeted run does not satisfy or complete official Phase 1D.3 or change the overall Lite result.

For local harness checks without GPU, run `/tmp/dacn-phase1d3-lite-test/bin/python -m pytest ai/tests/test_lite_smoke.py -q`. Do not treat scripted test responses as model evidence.

## Local checks

Use the CPU test environment described in `requirements.lock.pending.md`; do not install or replace PyTorch locally. Run `python ai/benchmark/validate_fixtures.py`, then the Python tests. The 120 fixtures are synthetic test inputs, not model output or quality evidence.

## Google Colab run order

1. Select a Tesla T4 runtime and follow `colab/phase-1d3.ipynb` from a clean reviewed Git commit or SHA-256-verified source archive. The notebook verifies the exact checkout. Before dependency work it records system Python/Torch/CUDA/GPU, `pip freeze`, Torch file hashes and a full file hash inventory of every system site-packages directory. If that system snapshot cannot be completed, stop.
2. In a separate Python 3.13/Linux resolver venv, create it with `--without-pip` and seed pip into that venv using Colab’s system pip `--python` option (the Colab runtime may not provide a working `ensurepip`); pin resolver-local `pip==25.1.1` and `click==8.4.2` for `pip-tools==7.5.2` compatibility, then install `pip-tools==7.5.2` inside the resolver, obtain the exact Torch wheel URL and SHA-256 from the official CUDA 13.0 index, download and verify that wheel, then create the full hash lock outside the source checkout. The lock includes the pinned Torch wheel and all direct/transitive dependencies. Keep it Pending until actual Colab resolver and dry-run evidence exists.
3. Create `/content/dacn-venv` with the system interpreter using `venv --without-pip`, then seed pip into that venv with system pip `--python`; never use `--system-site-packages`. Verify the venv configuration and interpreter. Run pip dry-run through `/content/dacn-venv/bin/python` with `--require-hashes`; the only permitted Torch operation is installing the exact locked official wheel into this fresh venv, with no uninstall. Install from the lock only after all source proof, wheel, lock, isolation and dry-run gates pass.
4. Verify system site-packages inventory and system Torch remain byte-for-byte unchanged. Verify the installed venv Torch `RECORD` against the downloaded official wheel. Run `pip check`, CUDA/device, NF4 import and pinned Qwen model-load checks with `/content/dacn-venv/bin/python`. Any mismatch blocks inference and leaves evidence Pending.
5. After model-load preflight passes, send one synthetic authenticated `/v1/infer` smoke request using the venv Python and save its redacted result. Require a successful response from the pinned Qwen model before continuing. The separate benchmark cell then restarts the runtime in observation mode, validates fixtures and runs all 120 fixtures with the same venv Python. Establish and separately verify the actual NestJS-to-runtime route; the local runner does not prove that route.
6. Review every output with `benchmark/rubric.md`; save one five-dimension score record per attempted fixture in `scores.json`. Failed and unattempted fixtures remain in the denominator.
7. Write `evidence.json` only after separately verifying real-model, lock, GPU, transport and analytical capacity evidence; set `ownerApproval` true only after explicit owner approval. Rerun the report. Missing evidence keeps the report Pending.
8. Return the full run directory, reviewed source commit/proof, external lock and wheel evidence, system and venv snapshots, fixture hash, attempts, evaluator outputs, manual scores, capacity measurements and transport evidence.

If a run times out or loses transport, restart the runtime process first. Resume only never-dispatched fixtures in a new run ID: rerun the same command with `--resume /path/to/prior-run --runtime-restarted`; the runner rejects a different fixture or config hash and carries prior attempts into the new denominator. A fixture marked ATTEMPTED without a finalized attempt becomes an INTERRUPTED failure and is never retried.
