> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development after independent Plan Review Gate approval. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small Colab demo lane that runs all six real AI tasks on a Tesla T4 with Qwen2.5-1.5B-Instruct FP16 and proves one real NestJS-to-FastAPI request.

**Architecture:** Reuse the existing AI Runtime, request envelope, prompts, task schemas, semantic/reference evaluator, and NestJS runtime client. **Tech Stack:** Existing Colab PyTorch, Transformers, FastAPI, NestJS runtime client, current JSON Schema/Ajv semantic/reference validators.

**Spec:** `docs/proposals/change-requests/CR-DRAFT-PHASE-1D3-LITE.md` (implementation is blocked until approved); approved full-phase plan `docs/superpowers/plans/2026-10-29-phase-1d3-real-model-benchmark.md` remains unchanged.

## Global Constraints

- Do not implement until the CR above is explicitly approved and this plan retains an Approved Plan Review Gate verdict.
- Preserve frozen baselines, AI Contract v1.0, Release 1 schema pack, public API, business rules, and `OPEN-ARCH-003`.
- Do not edit `ai/colab/phase-1d3.ipynb` or overwrite existing evidence.
- Demo candidate is `Qwen/Qwen2.5-1.5B-Instruct`, revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`, FP16; it is not a production selection.
- Reuse Colab's existing PyTorch without upgrading/replacing it; pin the detected Torch version in a temporary pip constraint and inspect a pip dry-run before installing any runtime dependencies. Stop if the resolver proposes any Torch operation. Do not run full Torch provenance, system-site-packages hashing, pip-compile, full benchmark, manual scoring, or capacity profiling.
- Keep NF4 as the runtime default; enable FP16 only through an explicit internal setting.
- For Lite FP16, fail load unless model parameters are actually on CUDA and FP16; the notebook independently confirms the selected GPU is a Tesla T4.
- Use synthetic fixtures and real inference only. Never repair output or convert a failed result to PASS.
- Keep runtime access private/loopback; do not create an automatic public tunnel or log secrets/raw prompts.
- Lite PASS is separate from official Phase 1D.3 acceptance; report official status as not complete.

- Smoke fixtures must contain exactly one valid synthetic input for each task, including the distinct Admin Stage 2 input.
- PASS requires HTTP 200, valid success envelope, matching contract/request/task correlation, expected model ID and task promptVersion, `schemaPass=true`, `semanticPass=true`, and `referenceStatus=PASS`. UNKNOWN, malformed, timed-out, non-correlated, or evaluator-error results are FAIL; do not retry automatically.

It proves the NestJS AI inference/gateway/runtime-client path only, with test doubles limited to authorization/eligibility, preflight, and the log repository; it does not claim the public business API or production capacity path.
- Store the actual parsed model output or returned error for each synthetic attempt in the Lite evidence; never store secrets or raw prompts.
- Existing Phase 1D.3 notebook, report, fixtures, plan, and evidence must remain unchanged.
