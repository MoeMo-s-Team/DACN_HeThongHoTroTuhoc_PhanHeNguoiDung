# AI Local WSL2 Runtime and Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` and execute this plan task-by-task. Keep Colab material until local hardware acceptance passes.

**Goal:** After CP-005 approval, validate the existing FastAPI Runtime on the target Windows 11/WSL2 RTX 3050 4GB in NF4, then archive only Colab-specific operational artifacts after a local acceptance PASS.

**Architecture:** Both developers have separate repository clones and run their own Next.js + NestJS. The user's Linux machine runs the Linux Tailscale client. Only the teammate's Windows 11/WSL2 GPU laptop starts one FastAPI/Qwen NF4 instance. The teammate's NestJS uses `AI_RUNTIME_URL=http://127.0.0.1:8000` after Windows-to-WSL access is verified. The user's Linux NestJS uses `AI_RUNTIME_URL=https://<gpu-host>.<tailnet>.ts.net` through Windows-host Tailscale Serve. Both NestJS `AI_RUNTIME_API_KEY` values match the one WSL `AI_RUNTIME_TOKEN`. Serve proxies the existing process; it must not launch a model. Keep FastAPI bound to WSL2 `127.0.0.1:8000`; no Funnel/public endpoint. Preserve bearer authentication, authorization, capacity preflight, contract and six tasks.

**Tech Stack:** Python 3.12, existing FastAPI Runtime, PyTorch CUDA wheel compatible with the Windows driver/WSL environment, Transformers, Accelerate, bitsandbytes NF4, Tailscale client on user's Linux machine and teammate's Windows host, Windows-host Tailscale Serve.

**Spec:** `docs/superpowers/specs/2026-10-30-ai-local-wsl-runtime-design.md`; governance hold: `docs/proposals/change-requests/CP-005-local-ai-runtime-wsl2-tailscale.md`.
