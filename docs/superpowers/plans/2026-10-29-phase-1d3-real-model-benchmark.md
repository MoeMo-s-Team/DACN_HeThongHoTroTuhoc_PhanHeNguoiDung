# Phase 1D.3 — Real AI Model Benchmark & Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development after independent Plan Review Gate approval. Steps use checkbox syntax.

**Goal:** Build a contract-compatible Colab AI runtime and reproducible evidence pipeline for six-task model selection, with actual GPU evaluation and approval remaining explicit gates.

**Architecture:** Python HTTP runtime on Colab loads a real pinned model, validates requests and observes output validity while preserving the backend error-classification boundary. Benchmark invokes the same inference path; the existing NestJS validator remains the authoritative semantic/reference oracle. Colab is a demo environment, not reliable hosting; no production profile is activated by this plan.

**Tech Stack:** Python 3.13, PyTorch CUDA, Transformers, Accelerate, bitsandbytes NF4, JSON Schema Draft 2020-12; existing NestJS/Ajv 8 and pnpm.

**Spec:** `docs/baseline/AI_Contract_v1.0_baseline_final.md` §§5–13, 16–18; `docs/releases/ai-contract-v1.0-schema-pack-release1/AI_Contract_v1.0_Erratum_1_approved.md`, CR-003 and Schema Pack Release 1; R3 and CR-002; `docs/baseline/System_Architecture_and_Technology_Stack_v1.1_baseline.md`; `ai/AGENTS.md` and root `AGENTS.md`.

## Global Constraints

- No change to frozen baseline/manifest, public API, gateway, authorization, business data, or feature callers. No database access, extra AI calls, silent truncation, retry, hardcoded secrets, or automatic public tunnel.
- POST `/v1/infer`; input envelope excludes `promptVersion`. Correlate `contractVersion`, `requestId`, `task`; task selects approved prompt metadata. Error codes and status mapping follow Contract §6.
- Prompt versions: `stu-learning-analysis-v1`, `stu-study-plan-v1`, `stu-study-adjust-v1`, `tea-class-analysis-v1`, `adm-feedback-group-v1`, `adm-feedback-summary-v1` in task order. Model choice remains open.
- Benchmark requires ≥20 valid inputs per task (≥10 normal and ≥10 boundary/adversarial), each actual attempt under 60 seconds, per-task schema and semantic ≥95%, zero reference violations, and per-task manual quality ≥4/5 over five dimensions. Missing/failed attempts count against rates; no real GPU evidence means Pending.
- Record profile candidates only, never activate a production capacity profile or close `OPEN-ARCH-003` without evidence and owner approval. Capacity includes a near-budget collection and, where applicable, large scalar per task and pre-dispatch overflow proof.
- Trace: UC-STU-004/005/009, UC-TEA-005/006, UC-ADM-004/005; FR matching those UCs; BR-007/008/013/014/015/018/021/026/028/034/035/036/037/041/042/043; API-STU-ANALYSIS-001, API-STU-PLAN-001, API-STU-ADJUST-001, API-TEA-ANALYSIS-001, API-ADM-ANALYSIS-001. No screen changes.

## Review Focus

- Missing/invalid request IDs and authentication must not leak secret or produce fabricated correlation.
- Model output malformed, incomplete, blank or with invented references must never count as valid; classify separately using backend oracle.
- Input longer than context must never be shortened; capacity must account for chat template, schema, output reserve and safety margin.
- Interrupted runs, duplicate fixture IDs, timeouts and manual-score omissions must not disappear from denominators or turn Pending into PASS.
- CUDA/version incompatibility, T4 OOM and absent GPU must produce explicit failed/blocked evidence, not a fake model response.

**Wire classification table (approved CR-004 / Erratum 2 E5–E6):** Runtime parses generated text but never repairs it. Parsed JSON objects pass unchanged in the correlated success envelope; NestJS remains authoritative for task schema/semantic validation. Only validated results may produce business success. For unparseable/empty/non-object generated output, use the existing correlated error envelope `INFERENCE_FAILED`, not a fake output or raw body. Malformed HTTP JSON received by NestJS and empty HTTP body retain existing gateway classification.

| Model/runtime result | Runtime HTTP response | Existing NestJS/API result and attempt |
|---|---|---|
| Parsed object passes task schema and semantics | 200 correlated Release 1 success envelope, object unchanged | success; one SUCCESS log |
| Parsed object violates type/enum/additionalProperties | 200 correlated success envelope, object unchanged | `502 AI_INVALID_STRUCTURE`; one FAILED log |
| Parsed object misses required field | 200 correlated success envelope, object unchanged | `502 AI_INCOMPLETE_DATA`; one FAILED log (existing required-key mapping) |
| Parsed object has required whitespace-only text | 200 correlated success envelope, object unchanged | `502 AI_INCOMPLETE_DATA`; one FAILED log (Erratum 1 E4 / CR-003) |
| Generated model text is malformed JSON, empty, or parses to non-object | 500 correlated Release 1 error envelope, `INFERENCE_FAILED` | `502 AI_RUNTIME_FAILURE`, internal `AI_RUNTIME_INFERENCE_FAILURE`; one FAILED log (CR-004 / Erratum 2 E5) |
| Malformed HTTP JSON reaches NestJS on 2xx | Runtime response body is malformed | `AI_INVALID_STRUCTURE`; one FAILED log |
| Empty HTTP body reaches NestJS on 2xx | Empty response body | `AI_EMPTY_RESPONSE`; one FAILED log |
| Worker unavailable / generation execution exception / timeout | Existing correlated `RUNTIME_UNAVAILABLE` / `INFERENCE_FAILED` envelope or transport timeout per Contract §6 | Existing mappings; one FAILED log; no retry |

Parsed invalid objects, missing fields, whitespace and generated-text parse failures must be covered by regression tests across all six tasks where task-shaped fixtures apply. Transport-body errors are task-independent, with correlation tested per task. No new codes, API shapes, retries, fake data, or log lifecycle changes. **Model output no longer parseable by Runtime is distinct from malformed HTTP JSON that NestJS receives.**
