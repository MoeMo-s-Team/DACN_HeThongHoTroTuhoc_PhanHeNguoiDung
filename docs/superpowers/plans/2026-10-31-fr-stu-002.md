# FR-STU-002 implementation plan

## Outcome and scope

Implement `GET /api/v1/student/assessment-results` and `/sinh-vien/ket-qua-hoc-tap` for `UC-STU-002` / `SCR-STU-002`. Keep the route student-only, use the authenticated user id and MVP Course, return at most the newest result for each Topic, validate persisted scores as 0–100, and use the API enum `GOOD | NEEDS_REINFORCEMENT | PRIORITY`. The UI shows topic, score, Vietnamese status, local `evaluatedAt`, and a CTA to `/sinh-vien/phan-tich-ai`; loading, empty, success, and error states are required.

No history/trend, AI call, new database behavior, generated result fixtures, or baseline edits. Reuse the existing Student module, AuthGuard/CurrentUser, shared score classifier, API client, TanStack Query, and Editorial Tech styling. Database Design permits additional Course rows but has no primary flag, so give the already seed-managed MVP Course a single shared stable id constant used by both the seed and Student service. The CTA target is the sitemap route `/sinh-vien/phan-tich-ai`; that screen is not implemented yet, so this task will add the specified link but will not claim the destination is complete.

## Approaches

- Add the endpoint and screen to the existing Student module/dashboard patterns (chosen): fewest new layers, shares auth and score classification.
- Create a separate assessment module/service: adds wiring and duplicates a single Student read flow.
- Return all results and select latest in the browser: violates backend authority and API semantics.

## Implementation steps

1. **Backend tests first:** extend `student-dashboard.service.spec.ts` for Student role/ownership query, primary-course scoping, latest result per Topic, `0/60/80/100` classifications, invalid scores, and empty results. Extend `student-dashboard.integration-spec.ts` for route auth/role/ownership, latest result, and empty response.
2. **Backend implementation:** add the shared stable MVP Course id constant and use it from the existing seed and Student service. Add response/item DTOs and the guarded route to the existing controller. Extract the dashboard's latest-per-Topic selection into one shared helper and reuse it for dashboard and result API; scope both to the Student and MVP Course. Validate score, then use the shared classifier. Correct the shared low-score enum to the API contract (`PRIORITY`) and update dashboard DTO, generated contract, and regression tests.
3. **Frontend tests first:** add `ket-qua-hoc-tap` tests for API-backed loading/empty/error/success, translated statuses, local date rendering, and the AI CTA route.
4. **Frontend implementation:** add the Student results page/component using the shared API client and TanStack Query. Match the existing Student Editorial Tech shell, responsive table/list, accessible status badges, and link to the sitemap's AI analysis route. Record that following the link will currently reach an unimplemented screen.
5. **Contract and verification:** regenerate OpenAPI contracts through the repository script if DTO/schema changes require it. Run relevant API/web tests, integration tests, typecheck/lint, and web/API builds; run baseline verification and `git diff --check`.
